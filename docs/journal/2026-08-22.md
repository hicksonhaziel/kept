# 2026-08-22 — day 22: kept meets code it did not write

Until today kept had been run against three projects: itself and its two bundled
fixtures. All three were written by the person writing kept. So today it met two
real libraries, and the results split cleanly into *the tool was right* and *the
tool was wrong*, which is the only useful kind of afternoon.

## itsdangerous — 5 kept, 1 unproven, 6.1 seconds

Pallets' signing library. Six criteria written from its documented behaviour, five
bound to its existing tests through a hand-written `.kept/bindings.toml` — no
`@verifies` markers, no edits to their test files. That path had never been
exercised outside a fixture.

Every bound promise reached **KEPT**: 12 mutants each, all noticed. The sixth
promise, about key derivation, has no test bound to it and says UNPROVEN.

This is the result the control fixture is supposed to predict, on code nobody
wrote for kept's benefit. A mature library's tests hold up under mutation, and kept
does not cry wolf.

## Starlette — three bugs, all mine

Two criteria bound to `tests/test_routing.py::test_router`, two to response tests.
kept reported all four UNPROVEN: *every bound oracle was skipped, missing, or
asserts nothing.*

**1. The suite had not run at all, and kept did not say so.** Starlette's test
suite needs jinja2, python-multipart, itsdangerous and typing_extensions to
collect. Without them pytest exits 2 and runs nothing. kept read the partial
report, found no outcome for anything, and labelled every oracle `notrun` — which
reads exactly like a verdict about the tests. It was a verdict about my
environment. Now pytest exit codes 2, 3, 4 and 5 raise, with the cause named and
the pytest output attached. Exit 1 deliberately does not: failing tests are
BROKEN verdicts, which is a real answer.

**2. Every parametrised oracle was reported as asserting nothing.** Starlette
parametrises almost everything over asyncio and trio, so its node IDs carry
`[asyncio]`. Vacuity shapes are keyed by the function a file defines, the lookup
missed, and an oracle whose shape cannot be found is treated as vacuous. That is
most oracles in most real suites, silently judged to constrain nothing. kept's own
suite has no parametrised bound test, so nothing caught it here.

**3. Binding a test by name reported it as missing.** `test_router` is real;
`test_router[asyncio]` is what pytest calls it. A bound ID now covers every
parametrisation, which is what `pytest path::test_router` already means. Recorded
as ADR-0007, including why fuzzy matching was refused.

With those fixed: **Starlette, 4 promises, 4 kept, 38.5 seconds** over an
863-test suite. The two bare bindings resolved to their asyncio and trio variants
and were judged on both.

## What this cost, and what it bought

Three defects, all invisible to 207 passing tests and to two fixtures, all found
within an hour of pointing the tool at somebody else's code. That is now the second
time in two days that leaving the workshop found a class of bug the workshop could
not: yesterday it was the mutated copy nobody imported, today it is the
parametrised oracle nobody could see.

The honest read of the pattern: kept's fixtures are too obedient. They were written
by the same hand as the tool, in the same idiom, so they exercise the paths the
author already had in mind. Real code is differently shaped, and that is the whole
value of running against it.

## Known limitations, written down rather than discovered later

- `--tests` takes one path. Starlette needed two files and got a pytest usage
  error for its trouble. It should be repeatable.
- A bound ID that matches nothing says `missing` and stops there. It could say
  *did you mean `test_router[asyncio]`* — kept knows the answer, since it has the
  full collection in hand.
- Neither project was Django. A Django suite brings a settings module and a
  database per test, which is the next shape kept has not met.
