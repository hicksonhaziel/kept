# 2026-08-19 — day 20: the surface an agent touches

Day 20 was the integration day: `kept prompt`, `kept serve`, Kiro hooks, and a
reusable GitHub Action. Four ways in, none of which is allowed to reach a verdict.

## What shipped

`kept prompt REQ-1.1` renders a remediation brief for one promise: the wording of
the promise, the recorded evidence, and the change that would answer it. It is a
pure function of the committed ledger — same ledger, same bytes.

`kept serve` speaks MCP over stdio behind the optional extra: `list_promises`,
`read_ledger`, `remediation_brief`, `verify`. The first three are annotated
read-only. `verify` can move a verdict, and it does so by running the same
pipeline the CLI runs.

Two Kiro hooks: `kept parse` after a write, `kept verify --gate no-regression` at
the end of a turn. The plan called the second one PostTaskExec, which is the IDE's
name; this CLI documents `stop`, so `stop` is what it is.

`action.yml` installs kept from the action's own checkout and exposes the tally as
outputs. kept's CI now runs it against kept's own fixtures.

## The decision that shaped the day

A WEAK verdict tells you an oracle is weak; it does not write the assertion. That
gap is exactly where a model wants to be, and `kept serve` makes the temptation
concrete: once an agent can call kept, the obvious next tool returns a patch.

I wrote ADR-0005 to close it. The brief is templated from the ledger, per verdict
and per UNPROVEN reason. It reads mechanically, which is the point — a brief that
reads like insight invites trust the ledger has not delegated. The agent proposes;
the ledger disposes. A `--suggest` flag that drafts the missing assertion was
considered and rejected: a tool built to catch oracles that agree with the code
they were written from should not ship a feature that writes oracles from code.

Every brief carries that disclaimer in its own text, because a brief travels — into
a PR comment, an agent's context, a scrollback — and has to stay honest away from
the tool that made it.

## The bug that mattered more than the features

`tests/report/__init__.py` disappeared from `git add -A`. Line 52 of `.gitignore`
was `_*.py`, meant for scratch scripts at the root. Unanchored, it matches every
`__init__.py`.

`src/kept/attack/__init__.py` and `src/kept/report/__init__.py` had never been
committed. On a clean clone:

    AttributeError: module 'kept.attack' has no attribute 'DEFAULT_CAP'

That is the README's own command failing on a fresh clone — the one failure kept
exists to make impossible to hide. It had been broken since day 18 and the working
tree never noticed, because the files were sitting right there on disk.

Patterns are now anchored (`/_*.py`). I verified the fix the only way that counts:
cloned the repository to /tmp, synced, and ran the documented commands. Control
fixture 5 kept, brief renders, 172 tests pass.

Unignoring those files also handed them to ruff for the first time — ruff skips
gitignored paths — which surfaced an unsorted `__all__` that had been invisible for
two days. Two lessons in one bug: an ignore rule is a hiding place, and a check
that cannot see a file cannot check it.

Also found: `ruff format --check .` has been in CI since day 14 and ten modules
from days 16 to 19 never satisfied it. The workflow had not run on a push since, so
nobody found out. Fixed in its own commit, formatting only.

## Honest gaps

- The new tests are deliberately **unbound**. `kept prompt` and `kept serve` have
  no acceptance criteria, and marking them `@verifies("REQ-6.1")` to make the
  traceability look complete would be precisely the misattribution kept detects.
  Criteria first, then bindings.
- `verdict.py` and `ledger.py` still have no unit tests. 172 tests and the two
  modules the entire ledger rests on are covered only through fixtures.
- kept still does not attest to itself. No `.kept/` at the root. That is day 21.
